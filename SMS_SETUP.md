# OTP SMS Habiterra

Habiterra generates and verifies the OTP. `SmsOtpSender` only sends that code
through Twilio Programmable Messaging. Twilio Verify is not used.

## Local configuration

Put real values only in the ignored `.env` file at the project root, or in the
process environment. Keep the existing database, JWT and email configuration.

```dotenv
OTP_DEV_MODE=false
TWILIO_ACCOUNT_SID=your_account_sid
TWILIO_AUTH_TOKEN=your_auth_token
TWILIO_FROM_NUMBER=your_sms_enabled_twilio_number_in_E164_format
```

With `OTP_DEV_MODE=true`, the existing development flow logs the generated code
and never calls Twilio. Missing Twilio configuration does not prevent application
startup or email delivery. It makes a real SMS request return HTTP 503 with
`OTP_DELIVERY_UNAVAILABLE`. The same applies to synchronous provider/network errors.
Do not enable HTTP wire/header logging: it can expose the SMS and credentials.

No automated tests are included for this integration, as requested.

## Manual test of the real OTP flow

This sends a real SMS and may incur Twilio charges. Use an account that permits
custom SMS content, a valid SMS-capable sender, and an allowed destination.
Restart the backend from the project root after changing `.env`.

```powershell
$otpBody = @{ identifier = '+221771234567' } | ConvertTo-Json
Invoke-RestMethod -Method Post `
  -Uri 'http://localhost:8080/api/v1/auth/request-otp' `
  -ContentType 'application/json' -Body $otpBody
```

Replace the example recipient with your own number, not already registered in
Habiterra. For resend, use `/api/v1/auth/resend-otp` with the same JSON after the
cooldown (60 seconds by default). The default hourly limit is five requests.
Check reception and the Twilio Messaging logs. API acceptance means the message
was submitted, not that the carrier delivered it. Asynchronous delivery failures
are visible in Twilio; this integration does not add delivery-status webhooks.

## Trial connectivity is separate from OTP delivery

Current Trial SMS documentation restricts message bodies to predefined templates,
such as `sms_2fa`. That template does not deliver the OTP generated by Habiterra.
Never substitute it in `/request-otp` or `/resend-otp`.

For a manual Trial connectivity check, open Twilio Console → Messaging → SMS →
Try out SMS, verify an eligible recipient and choose an allowed template. Use the
exact API example supplied by that console if testing via a separate REST client.
This is a provider connectivity test, not a successful Habiterra OTP registration.
No automatic Trial fallback or public diagnostic endpoint is implemented.

The documented SMS Trial currently mentions verified US recipients; the general
Trial documentation mentions the signup country. Check your console's actual
eligibility before assuming a Senegalese destination is available. Upgrade and
configure the destination permissions if required for custom OTP delivery.
